CRITICAL CODE SNIPPET
================================================================================

DEFAULT PERIOD CHANGE:
  File: enhancedDashboardStore.svelte.ts
  Line 22:
  
  CURRENT:
    let selectedPeriodType = $state<PeriodType>('month');
  
  CHANGE TO:
    let selectedPeriodType = $state<PeriodType>('year');

WHY THIS WORKS:
  - Store is created once on component mount
  - Initial state will be 'year' instead of 'month'
  - initialize() is called, which calls loadDashboardData()
  - Period.create('year', 0) creates current year period
  - buildModernUrl() generates /dashboard/year/2025
  - Charts render with yearly data
  - All dependent components automatically update via $derived

PERIOD OFFSET BEHAVIOR:
  offset = 0:  Current period (2025)
  offset = -1: Previous period (2024)
  offset = 1:  Next period (not allowed, shows current)
  
  Limits (enforced in navigatePeriod):
  - Month: -24 to 0 (2 years back, current)
  - Quarter: -8 to 0 (2 years back, current)
  - Year: -5 to 0 (5 years back, current)
  - Week: -52 to 0 (1 year back, current)

================================================================================
API ENDPOINTS SUMMARY
================================================================================

KEY ENDPOINTS:

1. /dashboard/enhanced/:year/:month
   → Current period metrics with categories
   → Used for initial dashboard load

2. /dashboard/history?months=N
   → Last N months of data
   → Used for charts and trend analysis

3. /dashboard/year/:year
   → Annual summary for specific year
   → Used for year-over-year comparisons

4. /dashboard/quarter/:year/:quarter
   → Quarterly metrics

5. /dashboard/current?type=month|quarter|year
   → Metrics for current period of specified type

6. /dashboard/range?startDate=...&endDate=...
   → Custom date range metrics

All endpoints return:
  {
    success: boolean,
    data: {
      summary: { income, expenses, investments, balance, ... },
      categories: [ { name, amount, percentage, ... } ],
      monthlyTrend: [ { month, income, expenses, balance } ],
      expenseDistribution: { essential, discretionary, ... },
      categoryBreakdown: [ ... ]
    }
  }

PERFORMANCE CONSIDERATIONS
================================================================================

CURRENT STATE:
  - Each period change: 1-2 API calls (compare, savings, history)
  - No caching: Same period requested again = new API call
  - Charts: Re-render on any store update (even unrelated state changes)

OPTIMIZATION OPPORTUNITIES:
  1. Data Caching (Highest ROI - could save 80% requests)
  2. Lazy Loading Charts (load summary first, charts in bg)
  3. Memoization of calculations (trends, seasonal patterns)
  4. Virtual scrolling for category lists
  5. Request deduplication (cancel in-flight requests if superseded)

RECOMMENDED QUICK OPTIMIZATION:
  Add simple cache to repository:
    const dataCache = new Map<string, DashboardData>();
  
  Check cache before API call, store result after success
  Clear on logout/currency change
  Could reduce API calls by 80% in typical usage patterns
